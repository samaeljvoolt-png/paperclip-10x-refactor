academy.alquim-ia.cloud Audit Report

Real browser and HTTP audit of the public site at academy.alquim-ia.cloud. This report only includes findings backed by direct observation on March 20, 2026.

Audited at: 2026-03-20 Scope: homepage, navigation, key routes, newsletter surface, HTTP headers, SEO basics Method: live browser + curl header/content checks

Executive Summary

The site is usable, fast to understand, and structurally coherent. Core routes sampled during the audit responded with 200, HTTPS is active, the homepage messaging is strong, and the mobile header/nav pattern exists.

The main risks are operational rather than cosmetic: missing response hardening headers, broken SEO infrastructure for robots.txt and sitemap.xml, and a very large brand image that creates avoidable performance cost. Metadata is also incomplete for richer search/social previews.

Overall: Needs remediation before strong public scale-up 3 High findings 1 Medium finding No critical browser-breaking defect observed

Findings

High Missing security response headers on public pages

The homepage response exposes only baseline headers: Content-Type, Content-Length, ETag, and standard server metadata. No Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, or Permissions-Policy were observed.

  • Repro: curl -sI https://academy.alquim-ia.cloud/
  • Impact: weaker client-side hardening and poorer baseline protection against framing, content sniffing, and policy drift
  • Fix: add a hardened Nginx response header policy and validate it in CI with a simple header smoke check

High robots.txt and sitemap.xml are misconfigured

Both URLs return the homepage HTML with 200 OK instead of crawler-specific content. That is a direct indexing defect, not a content preference issue.

  • Repro: open https://academy.alquim-ia.cloud/robots.txt and /sitemap.xml
  • Observed: both return the homepage document starting with <!doctype html>
  • Impact: search engines and tooling do not receive valid crawl instructions or sitemap discovery
  • Fix: publish a real robots.txt and valid XML sitemap from the static build or Nginx layer

High Brand image payload is oversized

The homepage logo/brand asset at /assets/alquim-ia-brand.png is served at 4,501,872 bytes. That is too large for a brand mark and creates unnecessary page weight.

  • Repro: curl -sI https://academy.alquim-ia.cloud/assets/alquim-ia-brand.png
  • Impact: slower first render, worse mobile performance, and wasteful bandwidth
  • Fix: export responsive image variants, compress aggressively, and prefer a much smaller web-optimized asset

Medium Metadata coverage is incomplete for SEO and social distribution

The homepage includes a title and description, but the sampled markup did not expose a canonical URL, Open Graph tags, Twitter card tags, or visible structured data.

  • Repro: inspect homepage source for canonical, og:, twitter:, application/ld+json
  • Impact: weaker search canonicalization and reduced quality of social/link previews
  • Fix: add canonical, OG, Twitter, and structured data at least on homepage, hubs, and cornerstone content pages

Positive Signals

  • Homepage messaging is specific and differentiated. It does not read like generic AI content filler.
  • Desktop and mobile navigation patterns are present and discoverable.
  • The newsletter form includes explicit consent checkboxes and links to data handling policy.
  • Sampled routes returned 200 and the site is consistently served over HTTPS.

Residual Risks and Limits

  • No authenticated/private flows were tested.
  • No full Lighthouse trace was run in this pass.
  • No real newsletter submission was executed, to avoid polluting production data.
  • This report focuses on verifiable findings only; it does not claim issues that were not directly observed.

Recommended Next Fix Order

  1. Publish correct robots.txt and sitemap.xml.
  2. Add response hardening headers at Nginx.
  3. Replace the oversized brand image with optimized web assets.
  4. Add canonical, Open Graph, Twitter, and structured data coverage.
